## Serving attempts — four routes, four walls

The vendor route is a matched pair: a modified SGLang runtime plus a matching modified FlashInfer, kept together in the repo's `eval/` tree, built by `eval/scripts/setup_eval_env.sh` into a uv venv. Attempts, in order:

1. **Setup as shipped (Python 3.10).** Dependency resolution fails outright: the pinned closure includes `torchcodec==0.9.1`, whose cu128 wheel exists only for x86_64. Inspection of the vendored SGLang showed torchcodec is used only for audio/video decoding — irrelevant to text serving — so the pin was dropped in the local lab copy (commented, with the reason recorded in the script). The environment then built cleanly (157 runtime + 34 scorer packages).
2. **Serve, stock torch.** The server died at distributed init: `CUDA error: no kernel image is available for execution on the device`. The stock torch 2.9.1+cu128 from PyPI's cu128 index carries arch list [sm_80, sm_90, sm_100, sm_120] — **no sm_110**. This box's GPU is sm_110; sm_120 is a different architecture and does not substitute.
3. **Jetson torch, same version.** The environment was rebuilt on Python 3.12 (the repo's `requires-python` is >=3.10, so this stays within the vendor's spec) and torch was swapped for the Jetson AI Lab build of the same version (2.9.1; arch list [sm_110, sm_121]; a CUDA matmul verified live on the GPU). torchvision 0.24.1's C++ extension then failed to load against it: `undefined symbol: _ZN3c104cuda29c10_cuda_check_implementationEiPKcS2_ib` — the Jetson torch build does not export a c10 CUDA symbol that stock-ABI extensions expect.
4. **The pairing already proven on this box.** The bench's own ml venv runs Jetson torch 2.11.0 + torchvision 0.25.0 daily, so that pair was imported into the eval venv: torch and torchvision then import cleanly, nms registers, arch list correct. The next import in SGLang's startup is its compiled kernel package, `sglang-kernel 0.4.1` (`sgl_kernel`), which fails with the **same undefined symbol** — and the build it ships is `sm100` only. The vendor runtime's kernel package is wedded twice over: to the stock-torch ABI and to datacentre architectures.

**Stopping rule, stated plainly:** the next step would be rebuilding sgl-kernel (and possibly parts of FlashInfer's compiled surface) from source against the Jetson torch for sm_110. That is a build project measured in hours with its own failure modes, not a bench step, so the model is recorded as **failed to serve on the Jetson AGX Thor** with the evidence above. The unblocking route is named for whoever picks this up: a Jetson-native build of the vendored SGLang's kernel package, or an upstream release of HybridDiffusion's runtime with sm_110 support. (The vendor validated on H100; nothing in the repo speaks to Jetson.)

## The technique — what FLARE is, from its own artefacts

FLARE converts a Qwen3.5 hybrid-attention autoregressive checkpoint into a dual-mode model in **one SFT stage** on roughly 10B tokens, with a token-equal joint AR + diffusion objective. The paper's own ablation worth remembering: transfer-data quality (their mix: 0.4 reasoning / 0.4 mathematics / 0.2 instruction) mattered more than the loss or mask design. Serving is organised around **two token streams through the same weights**:

- the **clean stream** — ordinary causal Qwen3.5 reading real tokens; it preserves the base model's capability;
- the **noisy stream** — the same network reading mask-noised inputs (mask token id 248077 in the Qwen3.5 vocab), which is what makes diffusion-style parallel proposals possible.

The two released interfaces differ in **where the trust boundary sits** — who is allowed to commit tokens:

| Interface | Trust boundary | Runtime entry | Released configuration |
|---|---|---|---|
| Diffusion-Trust | Commit noisy-stream samples through confidence-based block denoising | `LowConfidenceShiftHybridDiffusion` | runtime block 3 / generation 1 |
| AR-Trust | Treat noisy-stream samples as drafts and verify them with clean-stream logits | `HybridDiffusionSelfSpec` | block 7 / generation 4 |
| Causal | Decode left-to-right from the clean stream | Native SGLang causal decode | — |

**Diffusion-Trust** (config `hybrid_diffusion_shift_b3_g1.yaml`): the runtime block is `[current seed, MASK, MASK]`; a block denoises in parallel where per-token confidence clears **threshold 0.95**, and the block's final shifted logit becomes the next block's seed — so runtime `block_size: 3` implements the paper's logical block B=4. Prefill is causal (`causal_prefill: true`).

**AR-Trust** (config `hybrid_diffusion_self_spec_b7_g4.yaml`): self-speculation with horizon **N=4** and maximum active width **2N−1=7** — one anchor, up to three verification rows, three bidirectional draft rows. The noisy stream drafts; the clean stream's logits verify. The released policy is the paper's Exact-Truncated (`draft_mode: strict_truncated`); Softmax-Argmax and Truncated-Argmax verification remain available as explicit alternatives. It is speculative decoding with the drafter living inside the same weights, which is the elegant part: no second model to host, and the draft quality is the same network's own noisy-mode belief.

Read against the rest of this bench, FLARE is the only entrant whose diffusion is a *mode of an AR model* rather than a separate architecture — Nemotron-Labs Diffusion switches samplers on one checkpoint too, but its base is diffusion-native; FLARE's base is a production AR line with diffusion grafted on, and the trust-boundary framing (draft vs commit) is the vocabulary the graft makes necessary.
